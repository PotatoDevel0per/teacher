# 세미나 발표안 — 논문 흐름, 슬라이드별 (2026-10-20 구체화)

- 가정: 연구실 세미나 25분 + 질의 10분, 본문 16장 + 부록. 발표 시간·청중이 다르면 조정한다.
- 표시: 슬라이드마다 [완료] / [진행 중] / [계획]. 이전 실험은 [미검증].
- 용어: tonal, broadband, window, beating, Rec-disjoint(녹음 단위 분할), Ships-disjoint(선박 단위 분할).
- 미정 결과(ShipsEar E1-rep, E1-src)는 결과별 문구를 미리 준비해 두고, 발표 전날 숫자를 채운다.

---

## 1. 제목 (0.5분)

- 국문: 선박 분리 조건의 수중 표적 인식을 위한 물리 특징 조건부 잠재 확산 증강
- 영문: Physics-Conditioned Latent Diffusion Augmentation for Ships-disjoint UATR
- 부제: 연구 진행 보고 — 프로토콜·평가기·기준선 확보 단계

## 2. 문제: 누출이 성능을 부풀린다 [선행연구 + 재현] (2분)

- 핵심 메시지: **같은 선박이 train과 test에 함께 있으면 정확도가 12 pp 부풀려진다.**
- 그림: 막대 3개 — DeepShip Swin Mel Rec-disjoint 0.710 / Ships-disjoint 0.588 (UniqueShip 원문 Table II) / 우리 재현 Ships-disjoint 0.593
- 발표 노트: UniqueShip 원문은 선박 단위로 나누면 10–48 pp 떨어진다고 보고했다. 우리 재현값이 원문과 거의 같다는 것은 분할과 코드가 공개 결과와 맞는다는 뜻이다.

## 3. 가설과 동기 [선행연구] (1.5분)

- 핵심 메시지: **분류기는 클래스가 아니라 개별 선박을 외운다. 해결책은 "새 선박"을 보여주는 것이다.**
- 내용:
  - H-SC-1: Rec-disjoint에서 분류기는 선박 고유 단서를 쓴다.
  - 근거: 선박 수 2배 +2.4–2.6 pp, 녹음 시간 2배 +0.8–1.3 pp(UniqueShip Fig. 4). 같은 선박을 더 보는 것보다 다른 선박을 보는 것이 효과적이다.
  - 연구 질문: 생성 모델로 만든 "새 선박 같은" 샘플이 Ships-disjoint 성능을 올리는가?

## 4. 기여 (1분)

| | 기여 | 상태 |
|---|---|---|
| C1 | DeepShip·ShipsEar의 검증된 Ships-disjoint 5-fold 프로토콜 | 완료 |
| C2 | 생성물 평가용 물리 평가기 검증(tonal, DEMON의 beating 문제와 CPW) | 완료 |
| C3 | 선박 고유 단서가 broadband와 tonal 중 어디에 있는가 | 진행 중 |
| C4 | 물리 조건부 LDM 증강의 Ships-disjoint 효과 | 계획 |

- 발표 노트: 오늘 발표의 결과는 C1–C3이다. C4가 최종 주장이고 아직 결과가 없다.

## 5. 관련 연구 [문헌] (1.5분)

- 핵심 메시지: **기존 증강 연구 대부분은 누출이 있는 분할에서 평가됐다.**
- 표: 대표 연구 4–5개 × (방법, 데이터, 분할, 보고 이득). 출처 `research/literature/uatr_augmentation_survey.md`
  - 녹음 단위 분할의 LMR +3.72(Xu 2023), 생성 증강 +0.5–1.3, 무작위 분할에서는 +6–12
- 물리 특징 한 줄: LOFAR(tonal), DEMON(프로펠러 진폭 변조)
- LDM 한 줄: AE로 압축한 latent에서 diffusion, cross-attention 조건화(Rombach 2022)

## 6. 방법 개요: 게이트가 있는 파이프라인 [설계 완료] (2분)

- 그림: 6단계 흐름도와 각 단계의 게이트
  - 0 평가기 검증 → 1 AE 보존 → 2 무조건 LDM → 3 조건부(c_LOFAR → c_DEMON) → 4 조건 조작(새 선박 변이) → 5 UATR 판정(A0 / 범용 증강 / 비생성 물리 증강 / LDM 실제 조건 / LDM 조작 조건)
- 발표 노트: 한 단계에 한 변수만 바꾼다. 게이트를 통과하지 못하면 다음 단계로 가지 않는다.

## 7. 왜 게이트부터인가 [이론 + 미검증 이전 시도] (1.5분)

- 핵심 메시지: **LDM의 생성 품질 상한은 AE 복원이다. AE가 tonal을 지우면 diffusion은 되살릴 수 없다.**
- 근거: LDM 원문 §3 — diffusion은 E(x)만 학습하고 출력은 고정된 디코더를 거친다.
- 이전 시도 PG-MCLDM [미검증]: 생성물 tonal F1 0.2(실데이터 0.66), DEMON 변조 미생성(신뢰비 0.007–0.018), 증강 +0.66 pp(seed 1, 누출 분할)
- 발표 노트: 이번 설계는 이 실패에서 출발했다. 평가기, Ships-disjoint, seed ≥ 3, 사전 등록이 그 교훈이다.

## 8. 물리 평가기 [완료] (1.5분)

- tonal 평가기: 1 s window STFT, TPSW 배경 정규화, 피크 6 dB 이상, 5 s의 절반 이상 지속
- DEMON 평가기: band-pass 100–2000 Hz → **CPW 백색화(X/|X|)** → 포락선 → 최대 피크 / 배경 중앙값
- 원칙: 생성 조건 c와 평가 e는 서로 다른 추출기다(순환 논증 방지). 예: c_DEMON은 CT-VAE 후보, e는 고정 신호처리
- 그림: 합성 신호 검증(tonal 3개 회수, 8 Hz 변조 회수)

## 9. 실험 설정 [완료] (1.5분)

- 데이터: DeepShip 33,644 클립 / 244척 / 599 녹음, ShipsEar 2,223 클립 / 57척 / 90 녹음. 5 s, 16 kHz. UniqueShip은 코드 회귀 확인과 보조 실험용(정식 게재 전)
- 분할: Ships-disjoint 5-fold(검증: 공유 선박 0, 공유 녹음 0, 모든 클립이 test에 1회). 비교용 Rec-disjoint 5-fold
- 분류기: SwinV2-Tiny(ImageNet), UniqueShip 원문 설정
- 판정: fold paired Δ macro-F1, seed 3, **판정 규칙은 결과를 보기 전에 코드로 커밋**
- 발표 노트: DeepShip은 공식 분할이 없다. 선박 이름 매칭이 휴리스틱이라 불확실하면 묶는 쪽(더 엄격한 쪽)으로 처리했다.

## 10. 결과 1: 재현 [완료] (1분)

- 코드 회귀: UniqueShip acc 68.40 ± 2.46(기준 67.30 ± 2.45 범위 안), 이전 실험과 혼동행렬·학습 곡선이 비트 단위로 같음
- DeepShip Ships-disjoint MEL: acc 59.25 / F1 58.18 ↔ 원문 0.588 / 0.563
- 클래스별: Cargo가 가장 어렵다(F1 약 36), Tug가 가장 쉽다(약 69)

## 11. 결과 2: 어느 특징 도메인에서 생성할 것인가(E1-rep) [DeepShip 완료, ShipsEar 진행 중] (2분)

- 핵심 메시지(DeepShip): **MEL보다 나은 도메인이 없다.**
- 그림: fold별 Δ 점 그림(E1 결과 페이지 차트)
- 표: MEL 58.18 / CQT 56.44(Δ −1.74) / STFT 56.29(Δ −1.89) / MFCC 54.21(Δ −3.97). 모두 5 fold 중 1개만 양수
- 발표 노트: tonal이 가장 잘 보이는 CQT도 분류는 나아지지 않았다. 원인은 모른다(가설: 클래스 구별이 broadband에 의존, 또는 ImageNet 사전학습이 Mel에 맞음). 원문의 "Mel > STFT"와 같은 방향이다.
- ShipsEar 결과 문구(발표 전 선택):
  - 같은 방향이면: "두 데이터셋 모두 MEL이 최선 → E1-AE는 MEL + (CQT 또는 STFT)"
  - 다르면: "데이터셋마다 다르다 → 사전 규칙(평균 Δ)으로 상위 2개 선택"

## 12. 결과 3: tonal 평가기 [완료] (1분)

- AUC(실제 vs tonal을 지운 대조군): DeepShip 0.998, ShipsEar 0.937 → 사용
- 그림: 클래스별 tonal 수 분포(실제 10–16개 vs 대조군 거의 0)
- ShipsEar 배경 소음 클래스는 tonal이 없어 구별이 약하다(예상대로)

## 13. 결과 4: DEMON 평가기와 beating [완료] (2분)

- 핵심 메시지: **가까운 tonal 두 개가 만드는 beating을 프로펠러 박자로 착각한다. CPW 백색화가 이를 지운다.**
- 그림 1: 실패 사례 — 위상을 섞은 대조군에도 41.4 Hz 피크가 남음
- 그림 2: 합성 — beating 신뢰비 14.7 → 1.39, 날개 변조 23.5 → 20.5
- 표: AUC V1 / CPW / 하모닉 검출 — DeepShip 0.713 / **0.762** / 0.513, ShipsEar **0.720** / 0.683 / 0.540
- 결정: CPW로 통일한다. DeepShip은 사용하고 ShipsEar는 보류한다(사후 결정임을 명시)
- 하모닉 검출(기본·2배·3배 연속): 합성에서는 맞지만 실제 5 s 클립에서는 변조가 약해 90–97%가 0개 → 검출력 없음
- 근거 등급: CPW는 베어링 진단의 포락선 분석에서 쓰는 방법(인접 분야 근거). 수중 DEMON 사용례는 확인하지 못했다.

## 14. 결과 5: 선박 고유 단서는 어디에 있나(E1-src) [진행 중] (2분)

- 그림: 실제 클립의 스펙트럼 3종(O_rp / B broadband만 / T tonal만)
- 설계: 입력 3종 × Rec-disjoint·Ships-disjoint, 하락폭 D = drop(B) − drop(T)
- 결과 문구(발표 전 선택):
  - D > 0: "broadband 쪽에 선박 고유 단서가 더 많다. 단, 평활 한계로 D는 양(+) 쪽으로 치우쳐 있어 조심해서 해석한다"
  - D < 0: "tonal(정확한 기계 주파수)이 선박 고유 단서다. 치우침을 이기고 나온 결과다"
  - 0 포함: "구별되지 않는다"
- 발표 노트: 이 결과가 단계 4에서 무엇을 조작해야 "새 선박"이 되는지 정한다.

## 예상 질문과 답

| 질문 | 답의 요지 |
|---|---|
| 왜 아직 생성 결과가 없나? | 생성 품질의 상한은 AE이고, 평가기가 검증되지 않으면 생성 결과를 믿을 수 없다. 이전 시도가 그 순서를 건너뛰어 실패했다(7번) |
| 왜 UniqueShip을 주 데이터로 안 쓰나? | 정식 게재 전 arXiv 프리프린트다. 코드 회귀 확인과 보조 실험에만 쓴다 |
| 선박 분리 성능 58%는 너무 낮지 않나? | 공개된 같은 조건 값(0.588)과 같다. 낮은 값 자체가 연구 문제이고, 판정은 증강 전후 차이(Δ)로 한다 |
| 더 좋은 분류기를 쓰면 되지 않나? | test로 분류기를 고르면 결과가 부풀려진다. 분류기 3종 비교는 val 기준으로 최종 확인 단계에서 한다 |
| 5 s 클립으로 충분한가? | tonal은 충분하다(AUC 0.94–1.0). DEMON은 약하다. 더 긴 클립은 재검토 조건으로 남겼다 |
| 왜 CQT가 tonal을 잘 보는데 분류는 안 좋나? | 원인을 모른다. E1-src 결과가 실마리가 될 수 있다 |
| 이전 실험 결과는 왜 안 쓰나? | 분할이 폴더마다 다르고 누출이 있어 비교할 수 없다. 교훈으로만 쓴다 |
