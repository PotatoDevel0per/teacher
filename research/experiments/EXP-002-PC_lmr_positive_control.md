## 1. 목적

EXP-002에서 "선박 분리 조건에서 증강 효과 없음"이 나왔을 때 두 가능성을 구분해야 한다.
- 증강 구현이 틀렸다.
- 분할 때문에 효과가 사라졌다.

그러려면 **논문이 이득을 보고한 조건에서 우리 LMR 구현이 그 이득을 다시 내는지** 먼저 확인해야 한다.

> 질문: Xu J. 2023의 DeepShip 녹음 단위 분할, ResNet-18+MHA, STFT 조건에서 우리 LMR 구현은 논문의 이득(74.68 → 78.40, +3.72 pp)과 같은 방향, 비슷한 크기의 이득을 내는가?

- 이 실험은 **구현 검증**이다. 분할 단위가 이득을 줄이는지는 답하지 않는다. 그것은 EXP-002-PC(b)(UniqueShip naive vs MMSI)가 답할 질문이고, 아직 미승인이다.
- 정확한 표현: "논문의 LMR 모듈과 평가 프로토콜을 재현함(원문 미기재 세부는 §4에 기록한 값으로 채움)". **"논문 방법을 그대로 재현했다"고 쓰지 않는다.**
- Mel 입력 결과(+0.53 pp)는 재현 대상이 아니다. 우리가 측정한 실행 잡음(~1 pp, EXP-002 sanity check)보다 작아서 재현 여부를 판정할 수 없다.

## 3. 실험 arm

| arm | 내용 |
|---|---|
| B0 | 증강 없음 |
| B1 | LMR (§4.2) |

- 각 arm을 seed 3개(0, 1, 2)로 돌린다. 총 6 run.

## 4. 원문에 없는 세부와 채운 값 (모두 args.json과 보고서에 기록)

공식 학습 코드는 공개돼 있지 않다.
- 원문 각주 저장소 `xy980523/SmoothReg-LMR-...`는 2026-10-12에 조회되지 않았다(계정 404). 저자의 현재 계정 `YuanX9`에도 LMR 저장소가 없다.
- 같은 그룹의 `UATR-CMoE` 코드에는 attention pooling이 없다.

### 4.1 데이터·특징
| 항목 | 채운 값 | 이유 |
|---|---|---|
| val 15% 단위 | **녹음 파일 단위**, train 파일에서 클래스별로 층화, seed 고정 | segment 단위로 뽑으면 15 s overlap 때문에 train과 겹친다 |
| STFT | n_fft = win = 1600 (50 ms), hop = 800 (25 ms), Hann. 100–8,000 Hz bin만 남김(약 396 bin) | 원문의 400과 몇 bin 차이는 기록만 한다 |
| 진폭 | log(1 + |X|²) 또는 dB 중 하나로 고정해 기록. 정규화는 train 전체 평균·표준편차 | 원문 미기재 |
| 마지막 조각 | 30 s가 안 되는 끝부분은 버린다 | 원문 segment 수와 비교하기 위해 |

**데이터 확인 (실행 전)**: 우리 segment 수를 원문 6742 / 1190 / 2547과 비교해 보고한다.
- `/jhlee/UWShipNoise/data/deepship`은 Kaggle 미러(609 녹음)라서 원문 데이터와 다를 수 있다.
- test 2547과 5% 넘게 차이 나면 학습 전에 보고한다.
- Table 9 ID 중 우리 데이터에 없는 것도 보고한다.

### 4.2 LMR
| 항목 | 채운 값 |
|---|---|
| a, b 분포 | a ~ U{1, …, W−1}, b ~ U{1, …, H−1}, 서로 독립. 샘플마다 따로 뽑는다(원문 문장을 그대로 읽은 해석) |
| 패치 위치 | 패치가 입력 안에 완전히 들어가는 범위에서 균등 |
| 패치 개수 | 1개 |
| 짝 | batch를 무작위 순열로 섞어 i ↔ perm(i) |
| 적용 시점 | 정규화 후 특징(STFT)에 적용 |
| 켜는 단위 | batch마다 50% |

- **EXP-002 A1도 이 모듈을 그대로 쓴다.** A1은 원래 "CutMix 표준(λ ~ Beta(1,1))으로 근사"였다. 양성 대조군이 검증한 모듈과 EXP-002에서 쓰는 모듈이 같아야 대조군의 의미가 있으므로, A1 실행 전에 바꾼다.
- 단, UniqueShip Mel(256×256)에 적용할 때도 위 규칙은 그대로다.

### 4.3 모델
- torchvision ResNet-18 구조, 입력 1채널, 무작위 초기화(사전학습 없음).
- 마지막 avgpool 대신 **QKV attention pooling**: CLIP 방식 `AttentionPool2d`를 쓴다.
  - feature map 위치에 학습 가능한 위치 임베딩을 더한다.
  - 전역 평균 토큰을 query로 쓴다.
  - embed 512, head 8.
  - 그다음 FC(4클래스).
- 원문은 head 수와 차원을 적지 않았다. 파라미터 수를 세어 11.8 M과 함께 보고한다.
- 입력 크기가 가변이면 위치 임베딩 크기를 1199×~396 입력의 feature map에 맞춘다.

### 4.4 학습·선택
- AdamW lr 5e-4, wd 1e-5, batch 64, 100 epoch, 스케줄러 없음(원문 미기재 → 없음으로 고정).
- 체크포인트: **best val accuracy**(원문 미기재). 마지막 epoch의 test accuracy도 함께 기록한다.
- test는 학습이 끝난 뒤 한 번만 평가한다.

## 5. 판정 (사전 등록, 결과를 보기 전에 고정)

주 지표: seed별 Δ_s = acc(B1, s) − acc(B0, s), test segment 정확도, best-val 체크포인트 기준.

| 판정 | 조건 |
|---|---|
| **재현됨** | Δ_s > 0인 seed가 3개 모두이고, 평균 Δ ≥ 2.0 pp |
| **부분 재현** | 평균 Δ > 0이지만 위 조건을 다 채우지 못함 |
| **재현 안 됨** | 평균 Δ ≤ 0 |

- baseline B0 평균은 원문 74.68과 비교해 보고만 한다. 판정에는 쓰지 않는다. 데이터 미러, 정규화, 체크포인트 규칙이 달라서 절대값 일치는 기대하지 않는다.
  - 단, B0 평균이 65% 미만이거나 85% 초과면 파이프라인 오류를 의심하고 **판정 전에 보고**한다.
- 판정에 따른 다음 단계:
  - 재현됨 → EXP-002를 재개한다(② 반영, A0 5 fold 재실행부터).
  - 부분 재현 / 재현 안 됨 → EXP-002 A1을 보류하고 teacher 세션과 원인을 검토한다.
    - 검토 순서: 구현 오류 → 데이터 미러 차이 → 원문 단일 실행의 우연.

## 단계 2: baseline 절대값 재현 (2026-10-12, 사용자 요청)

사용자 판단: "증강이 있어도 정확도가 70%대 정도는 나와줘야 의미가 있다. 70% 재현을 먼저 할 수 있어야 한다."

### 목표 (사전 등록)
- **B0(증강 없음)의 test 정확도 3 seed 평균 ≥ 70%.** 원문 74.68에 가까울수록 좋다.
- **test는 선택에 쓰지 않는다.** 원문에 없는 값 중 어떤 것을 고를지는 **val 정확도로만** 정한다. test는 기록만 한다.
  - test로 고른 epoch에서만 70%를 넘으면 "재현"으로 치지 않는다. 그 경우에는 "원문 수치가 test 기반 선택에 의존했을 가능성"으로 보고한다.

### 진단 순서 (한 번에 하나만 바꾼다. B0 seed 0, run당 약 1시간)
| ID | 바꾸는 것 | 목적 |
|---|---|---|
| D1 | 없음. epoch마다 test 정확도를 **기록만** 한다 | 선택 방식의 상한을 본다. epoch 중 최고 test가 70% 이상인가? |
| D2 | val을 segment 단위 15% 무작위로 뗀다(원문 추정 방식). 학습 녹음 수가 원문과 같아진다 | 학습 녹음 69개 손실의 영향 |
| D3 | lr 스케줄: cosine decay(100 epoch) | 원문 미기재. 지금은 val이 epoch마다 ±5 pp 흔들린다 |
| D4 | 진폭 표현: dB(20 log10 \|X\|) + 샘플별 정규화 | 원문 미기재 |
