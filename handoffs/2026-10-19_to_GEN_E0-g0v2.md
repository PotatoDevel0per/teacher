# Handoff → GEN: E0-G0 v2 — DEMON 평가기 두 가지 수정의 판별력 (백색화 / 하모닉 family 검출)

- 작성: 2026-10-19 (Teacher). 받는 곳: `GEN` (`/jhlee/UWShipNoise/thesis`)
- 근거: G0 v1 결과(thesis 3885ae9). DeepShip DEMON AUC 0.693(보류), ShipsEar 0.709(경계). 원인 진단: (1) 대역 안의 tonal 쌍이 만드는 beating(차주파수 박자)가 위상 무작위 대조군에도 남는다. (2) 2 Hz 근처의 저주파 솟음이 최대 피크로 잡힌다.
- 사용자 결정 (2026-10-19):
  - 백색화와 하모닉 검출을 **둘 다** 시험한다.
  - 하모닉은 점수가 아니라 **3번 이상 반복되면 있음**으로 판정한다.
  - 한 DEMON 안에 **서로 다른 하모닉 구조(component)가 둘 이상** 있을 수 있으니 모두 검출한다.
- 공동 작업 규칙은 v1 지시서와 같다(GEN 경로 `core/evaluate/`, `exp/E0_g0/`만 수정, 자기 경로만 커밋, GPU 사용 안 함).

## 1. arm (v1 평가기 대비 한 가지씩만 바꾼다)

| arm | 바꾸는 것 | 판독 |
|---|---|---|
| V1 | 없음(v1 평가기 그대로, 새 표본에서 다시 잼) | 최대 피크 / 배경 중앙값 |
| W | band-pass 뒤, 포락선 전에 **스펙트럼 백색화** | V1과 같음 |
| H | 판독만 **하모닉 family 검출**로 바꿈 | family 수 |
| W+H (보조) | 둘 다 | family 수 |

- 대조군(위상 무작위화), band-pass 100–2000 Hz, 포락선·다운샘플·FFT 설정은 v1과 같다.
- W+H는 보조 arm이다. 판정은 하지만 결론은 W, H 단독 결과를 먼저 본다.

## 2. W: 스펙트럼 백색화 — **정정 (2026-10-19): cepstrum pre-whitening(CPW)으로 변경**

- **새 방식:** band-pass 범위 안에서 X_w = X / |X| (위상 유지, band 밖 0) → 역변환 → v1 포락선·판독. 근거(인접 분야): 베어링 진단에서 포락선 분석 전에 discrete 성분을 제거하는 CPW, x_cpw = IFFT(FFT(x)/|FFT(x)|) (Sensors 2023, PMC10674700 §2.1 확인; Borghesani et al. 2013 MSSP 36(2):370–384 서지 확인).
- **정정 이유:** 아래 원래 방식(median 평활값으로 나눔)은 broad 기울기만 평평하게 하고 tonal 피크를 남겨 beating(원인 1)를 줄이지 못한다. 설계 오류였다.

(원래 지시, 폐기)

- 클립 rfft의 band 안 진폭 |X|를 주파수 방향 median(약 20 Hz, v1 tonal 대조군과 같은 창)으로 평활한 값으로 나눈다. 위상은 그대로 둔다. 역변환한 뒤 포락선을 구한다.
- 주의: Teacher가 원문 근거를 확인하는 중이다(베어링 진단의 cepstral pre-whitening 등). 근거가 다른 방식을 가리키면 별도 arm으로 추가할 수 있다. 이번에는 위 방식으로 고정한다.

## 3. H: 하모닉 family 검출 (근거: Hashmi & Raza 2023 DEMON 판독 규칙. beating 제거 효과는 신호처리 추론)

DEMON 스펙트럼(0–100 Hz, bin 0.2 Hz)에서:

1. **피크 검출:** 국소 극대 중, 주변 배경(±2 Hz 창에서 피크 ±0.4 Hz를 뺀 중앙값)보다 **6 dB 이상** 큰 것. 탐색 범위는 2–100 Hz다.
2. **family 정의:** 기본 주파수 f0 ∈ [2, 33] Hz에 대해, 피크가 n·f0 (n = 1…⌊100/f0⌋) 위치 **±0.3 Hz** 안에 있으면 그 family의 member다.
   - **family 성립 조건: n = 1(기본) 피크가 있고, member가 3개 이상이다.** 빠진 차수는 허용한다(Hashmi: 다음 하모닉이 있으면 있는 것으로 봄).
   - ±0.3 Hz는 Hashmi의 허용오차 0.1–0.3 Hz의 상한이다. 5 s 클립의 bin은 0.2 Hz다.
3. **여러 component 분리 (사용자 요구):**
   - 성립한 family를 member 수 내림차순(같으면 f0 오름차순)으로 정렬한다.
   - 이미 채택한 family A가 있을 때, 후보 B의 f0_B / f0_A가 정수 ±0.03 이내면 B는 A의 일부(같은 축의 날개 하모닉 등)로 보고 새 component로 세지 않는다. f0_A / f0_B가 정수 ±0.03 이내인 경우(B가 A의 기본보다 낮은 기본)에는, B의 member 중 A가 아직 갖지 않은 member가 2개 이상일 때만 B를 채택하고 A를 B에 합친다.
   - 그 외(비율이 정수 관계가 아니면)는 서로 다른 component로 채택한다. 한 피크는 여러 family의 member가 될 수 있다.
   - 출력: component 수, 각 component의 f0·member 차수 목록.
4. **AUC 지표:** 클립당 component 수(0, 1, 2, …). 동률은 AUC 계산에서 0.5로 센다.

## 4. 합성 단위 테스트 (실데이터 전에, 통과해야 다음으로)

| 테스트 | 신호 | H 기대 |
|---|---|---|
| H1 beating | 1000 Hz + 1041 Hz tonal + broadband 잡음 | component 0 (41 Hz 단일 피크) |
| H2 프로펠러 | 축 2 Hz, 날개 4 → 8 Hz 펄스열 진폭 변조 | component 1 (f0 = 2 또는 8, 하모닉 ≥ 3) |
| H3 두 component | 8 Hz 펄스열 변조 + 11.3 Hz 펄스열 변조(다른 대역 반송) | component 2 |
| H4 잡음만 | broadband 잡음 | component 0 |
| H5 하모닉 tonal 빗 | 대역 안 f₀ = 37 Hz 간격 tonal 10개 | 기록만(한계 확인용. beating 빗이 family로 잡힐 수 있음) |
| W1 | H1 신호에 W 적용 후 v1 판독 | 41 Hz 피크의 신뢰비가 줄어야 함(기록) |

- H2는 f0 = 2 Hz(축)와 8 Hz(날개) 중 무엇으로 나오는지 기록한다. 두 개로 세면 실패다(3번 규칙 위반).
- H5는 판정에 쓰지 않는다. 한계를 기록하는 용도다.

## 6. 판정 (사전 등록, 결과를 본 뒤 바꾸지 않는다)

- 데이터셋별 AUC(실제 vs 위상 무작위 대조군) ≥ 0.70이면 그 arm의 DEMON 평가기를 사용 가능으로 본다.
- 여러 arm이 통과하면 AUC가 가장 높은 arm을 채택 후보로 보고한다. 0.02 이내 차이면 더 단순한 arm(V1 < W, H < W+H 순)을 고른다.
- 모두 미달이면 그 데이터셋에서 DEMON 조건·평가는 쓰지 않는다.
- 보조 보고(판정 무관): 실제 클립의 component 수 분포(0/1/2/3+), 클래스별, component f0 분포, 대조군의 거짓 component 사례 5개.
