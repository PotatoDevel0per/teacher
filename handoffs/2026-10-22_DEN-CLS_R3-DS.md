# Handoff → DEN·CLS: R3-DS — ShipsEar 학습 잡음 제거기를 DeepShip 분류 앞단에 (누출 없음)

- 작성: 2026-10-22 (Teacher). 사용자 결정(2026-10-22):
  - 잡음 제거기도 분류기의 test 선박을 보지 않아야 한다(일관성 원칙).
  - R3-SE(ShipsEar 전체로 학습한 잡음 제거기 → ShipsEar 분류)는 누출이므로 **돌리지 않는다.** 캐시는 참고용으로 남긴다.
  - R3-DS를 먼저 한다. R2c는 계속 돌리고, 그 결과는 잡음 제거 성능 확인용으로만 쓴다. ShipsEar fold별 잡음 제거기(R5)는 R3-DS 결과를 보고 정한다.
- 누출 확인: R2 통과 모델(시도 2b)은 ShipsEar 선박과 배경만으로 학습했다. DeepShip은 본 적이 없다.
- GPU: R2c(DDP 2장, 장당 약 8.4 GB)와 **같은 GPU를 함께** 쓴다. 메모리 합이 24 GB를 넘지 않게 한다. 결과 수치는 같고 속도만 느려진다.

## DEN

1. thesis DeepShip 로더와 같은 방식(32 kHz → soxr VHQ 16 kHz)으로 DeepShip 녹음 전체(clips.csv가 가리키는 녹음)를 불러온다. 시도 2b `denoise()`(3 s 창, 50% overlap-add)를 **녹음 단위로** 적용한다.
   - GPU 0에서 추론한다(R2c와 공유). 출력은 `outputs/deepship_denoised/<클래스>/<녹음>/<파일명>.wav`(16 kHz float32, 입력과 같은 길이)이고 manifest를 둔다.
2. 확인: 길이 일치, NaN·Inf 없음.
3. 실녹음 진단은 R2b에서 fold1 test로 이미 쟀다. 이번에는 전체 클립 기준 요약(지운 에너지, tonal 수, LTAS)만 다시 낸다.
4. 커밋하고 경로를 보고한다. README에 "누출 없음(DeepShip 미학습)"을 적는다.

## CLS

1. 레지스트리에 `deepship_den`을 추가한다. 클립 정의(33,644, unmatched 제외 규칙 동일)와 shipcv 분할은 원본과 같게 두고, 경로만 바꾸고, 리샘플은 하지 않는다(편차).
2. 자동 점검(check_den과 같은 항목) → MEL 캐시를 만든다.
3. 학습: E1-rep DeepShip v2 설정(best-val, ReduceLROnPlateau, patience 8, lr 1e-6), MEL × 5 fold × seed 0,1,2 = **15 run**. DDP 2장이며 R2c와 공유한다.
4. 판정(사전 등록, `exp/R3_ds/summarize.py` 먼저 커밋):
   - Δ = F1(잡음 제거) − F1(원본, E1-rep deepship_MEL), fold별 seed 평균, paired
   - "도움": 평균 Δ > 0 & 4/5 fold 이상 Δ > 0
   - "해로움": 평균 Δ < 0 & 4/5 fold 이상 Δ < 0
   - 그 외 "판단 불가"
   - 보조: acc, 클래스별 F1(특히 Cargo), seed sd, DEN 실녹음 진단 요약
