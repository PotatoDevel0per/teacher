# Handoff → GEN: EXP-E1-AE — 도메인별 AE 보존 게이트

- 작성: 2026-10-21 (Teacher). 받는 곳: `GEN` (`/jhlee/UWShipNoise/thesis`)
- 근거: EXP-003-LDM 설계 §4 단계 1(G1), §10 E1-AE, D-2026-10-21-01(대상 도메인 MEL + STFT + CQT), LDM 원문 노트 `papers/notes/2022_rombach_ldm.md`
- 질문: AE가 실데이터의 클래스 정보와 tonal을 latent에 **잃지 않고** 담는가? LDM 생성 품질의 상한은 AE 복원이다(원문 §3). 이 게이트를 통과한 도메인에서만 LDM을 학습한다.

## 0. 진행 순서와 자원

1. **CPU 작업(지금):** `core/ae/` 구현, 단위 테스트, 게이트 평가 코드. 판정 스크립트를 먼저 커밋한다.
2. **GPU 작업:** CLS의 E1-src(약 05:30 UTC 종료 예정)가 끝난 뒤 시작한다. 그 전에는 GPU를 쓰지 않는다. 끝났는지는 `nvidia-smi`로 확인하거나 CLS에 묻는다.
3. 공동 작업 규칙: GEN 경로는 `core/ae/`, `core/evaluate/`, `exp/E1_ae/`이다. 다른 경로는 import만 하고, 커밋은 자기 경로만 `git add`한다.

## 1. 입력과 분할 (기존 자산 재사용)

- 입력: E1-rep 캐시의 256 × 256 특징 이미지(MEL, STFT, CQT; DeepShip·ShipsEar). 분류기에 들어가는 것과 **같은** 값 범위·정규화를 쓴다. 정확한 전처리는 `core/train_cls.py`와 `core/features.py`를 읽어 맞춘다.
- 분할: `core/splits/{deepship,shipsear}_shipcv_fold{1..5}.json` (Ships-disjoint).
- **AE는 fold k의 train 클립만으로 학습한다.** test 선박을 보면 안 된다. 체크포인트 선택은 fold k의 val 복원 L1로 한다.

## 2. AE 사양 (한 가지 설정으로 고정, 변형 금지)

- 구조: 2D conv encoder·decoder(residual block), 다운샘플 f = 4(주파수·시간 모두 → latent 64 × 64), latent 채널 C = 4. 압축비 256² / (64² × 4) = 4.
  - 근거: 원문 §4.1에서 f = 4–8이 최선이었다. 가장 덜 압축하는 쪽에서 시작한다.
- 정규화: KL 가중치 1e-6(원문 부록 G). 학습 후 train latent의 전체 표준편차 σ̂를 저장한다(이후 LDM의 latent 재스케일용).
- 손실: **복원 L1만** 쓴다. adversarial, LPIPS, 물리 손실은 넣지 않는다.
  - LPIPS는 ImageNet VGG라 스펙트로그램에 근거가 없다.
  - adversarial과 물리 손실(H-LDM-1)은 게이트가 실패할 때 하나씩 넣을 다음 변수다.
- 학습: AdamW lr 2e-4(구현 휴리스틱), batch 32, 상수 lr. step 수는 DeepShip 20k, ShipsEar 10k로 고정한다. 1k step마다 val L1을 재고 최저 checkpoint를 쓴다. seed 0.
- 규모: 도메인 3 × 데이터셋 2 × fold 5 = AE 30개. 첫 AE의 소요 시간을 재서 전체 예상 시간을 먼저 보고한다.

## 3. 게이트 (사전 등록, 결과를 본 뒤 바꾸지 않는다)

### (a) 클래스 보존: 도메인 간 비교용

- fold k의 실데이터 분류기를 fold k test의 **원본**과 **AE 복원본**에 각각 적용한다.
  - 분류기: CLS의 E1-rep seed 0 체크포인트. DeepShip은 `best.pt`, ShipsEar는 `last.pt`(E1-rep 주 지표와 같은 것). 경로는 `exp/E1_rep/results/<dataset>_<ARM>_fold<k>_seed0/`.
- 지표: r = macro-F1(복원) / macro-F1(원본). acc 비율도 함께 기록한다.
- **통과: 데이터셋마다 5 fold 평균 r ≥ 0.95**(구현 휴리스틱). 두 데이터셋을 따로 판정한다.

### (b) tonal 보존: 도메인 안에서만

- 특징 이미지의 시간 평균(주파수 축 프로파일, 256칸)에서 피크를 찾는다. 기준: 주파수 방향 median baseline보다 6 dB 이상 높은 국소 극대. baseline 창은 도메인마다 약 20 Hz에 해당하는 칸 수로 정한다(저주파 기준). 정한 값은 REPORT에 적는다.
- 원본 피크를 정답으로, 복원본 피크의 P/R/F1(±1칸)을 계산한다. 평가 범위는 10–1000 Hz에 해당하는 칸이다.
- **통과: 도메인·데이터셋마다 test 클립 평균 F1 ≥ 0.80**(설계 §4 G1 제안값).
- **평가 불가:** 원본 이미지에서 클립당 피크 수의 중앙값이 2 미만이면 그 도메인의 (b)는 "평가 불가"로 표시한다. 판정은 (a)만으로 한다. STFT(칸당 31 Hz)는 여기에 해당할 가능성이 크다.
- DEMON은 이미지(프레임 16 ms)에서 잴 수 없으므로 이번 게이트에 넣지 않는다.

### (c) 보조 (판정 무관)

- 복원 L1, PSNR, 클래스별 F1 비율, latent σ̂, 복원 예시 그림(클래스별 2클립 × 도메인)
- **2026-10-21 추가(학습 전, 사용자 승인):** 예측 일치율(클립별 argmax가 원본·복원본에서 같은 비율, 클래스별 포함), LTAS 거리(시간 평균 256칸 프로파일의 원본 대비 RMS dB, 전체·≤1 kHz)

### 결론 형식

- 도메인마다: (a) 통과 여부 × 데이터셋, (b) 통과 / 미달 / 평가 불가.
- 통과한 도메인이 LDM 단계 2의 후보다. 모두 실패하면 다음 변수(adversarial 손실 → 물리 손실 H-LDM-1)를 하나씩 넣는 실험을 Teacher가 지시한다. 두 번 실패하면 LDM을 보류한다(D-2026-10-06-01).

## 4. 단위 테스트 (CPU, GPU 작업 전)

- forward/backward shape, KL 항 크기, 결정적 재현(같은 seed면 같은 출력)
- (b) 평가기: 합성 이미지(알려진 칸에 피크 3개 + 잡음)에서 F1 = 1, 피크를 지운 이미지에서 recall 0
- 분류기 로딩: 원본 test로 E1-rep에 기록된 test 지표가 그대로 재현되는지 fold 1개에서 확인한다(일치해야 함). 이것이 (a) 파이프라인의 회귀 확인이다.
