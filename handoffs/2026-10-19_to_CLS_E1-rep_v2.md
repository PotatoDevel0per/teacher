## 1. 단계 S: 선박 단위 5-fold 분할 (한 번 만들고 고정)

입력(읽기 전용):
- DeepShip 클립: `/jhlee/UWShipNoise/recognition/UATR_SLM/data/clips/clips.csv` (33,770 클립, 5 s, `ship_id`, `ship_source`, `recording_id`)
- ShipsEar 클립: `/jhlee/UWShipNoise/recognition/UATR_SLM/UATR_SLM_split_study/04_splits/shipsear_clips.csv` (2,223 클립), 녹음·선박표: `.../shipsear_inventory.csv` (90 녹음, 57척), 원본 녹음: `/jhlee/UWShipNoise/legacy/Underwater_Acoustic/LIG_Diffusion/Datasets/ShipSEAR/AUDIOS/`, 캐시 생성 코드: `.../04_splits/code/build_shipsear_cache.py`

그룹(누수 단위) 규칙:
- DeepShip: 그룹 = 선박 이름(`ship_id`의 `::` 뒤, 대문자·공백 정규화). 잘린 이름 "QUEEN OF"(35 녹음)는 하나의 그룹으로 둔다(보수적 병합: 불확실하면 묶는다).
- DeepShip `ship_source == unmatched`(Tanker 10 녹음, 126 클립)는 **모든 fold에서 제외**한다. 다른 선박과 같은지 알 수 없기 때문이다.
- ShipsEar: 그룹 = `ship_id`. 클래스 E(배경 소음)는 녹음 단위가 그룹이다.
- 확인 완료(Teacher): 두 데이터셋 모두 같은 이름이 두 클래스에 나타나지 않는다.

fold 배정:
- 클래스별로 그룹을 5 fold에 배정한다. 각 fold의 클래스별 클립 수가 그 클래스 전체의 약 20%가 되도록 한다. 랜덤 재시작 그리디, seed 0 고정. split_study의 `make_splits.py` 방식을 참고해도 된다.
- 제약: 모든 test fold에 모든 클래스의 그룹이 1개 이상 있어야 한다.
- fold k: test = fold k. val = 나머지 train 그룹에서 클래스별 약 15%(클래스당 최소 1그룹, seed 0). train = 나머지.
- 출력: `core/splits/{deepship,shipsear}_shipcv_fold{1..5}.json` (`split.train/val/test` = 클립 인덱스, `assign` = 그룹 → fold, 메타에 생성 코드 git hash). 생성 스크립트와 `core/splits/SPLITS.md`.
- 검증(실패하면 단계 B 금지):
  - 각 fold에서 train/val/test 사이 공유 그룹 0, 공유 녹음 0
  - 모든 클립이 정확히 한 번 test에 들어간다(제외분 제외)
  - fold × 클래스별 그룹 수·녹음 수·클립 수 표를 SPLITS.md에 쓴다

## 2. 단계 F: 특징 (CLS 질문에 대한 결정)

공통: 16 kHz, 5 s 클립, n_fft 2048(창 1024, zero padding), hop 256, Hann → 312 프레임. DeepShip은 32 kHz → 16 kHz, ShipsEar는 52,734 Hz → 16 kHz. 리샘플은 split_study 캐시와 같은 방식(soxr VHQ)을 쓴다. 두 데이터셋 모두 UniqueShip과 같은 312 프레임이므로 시간 축 처리(312 → 256)는 EXP-001과 같다.

| arm | 결정 |
|---|---|
| MEL | EXP-001과 동일 |
| STFT | **CLS 제안 채택.** Nyquist bin을 버린 1024 bin을 power 영역에서 4 bin 평균(area)해 256 bin(각 31.25 Hz)으로 만든다 → dB → 90 dB 범위 → 시간 축만 EXP-001 방식으로 리사이즈 |
| CQT | **채택.** librosa 0.11.0, f_min 20 Hz, bins_per_octave 30, 256 bin(최고 약 7.24 kHz), hop 256. 최저 bin 창 약 2.1 s를 REPORT에 적는다 |
| MFCC | **CLS 제안 채택.** log-mel 256에 DCT, 40 계수 → fold train 통계로 계수별 z-score. ImageNet 정규화는 생략한다. 이것은 다른 arm과의 편차로 REPORT에 적는다(참고용 arm) |

- 캐시: 디스크가 부족하면 DeepShip·ShipsEar 캐시만 만든다(UniqueShip 새 캐시는 만들지 않는다). 크기를 먼저 추정해 알려 준다.
- 확인: 각 특징에서 클래스별 샘플 몇 개를 그림으로 남긴다(`exp/E1_rep/figs/`). 50–400 Hz tonal이 STFT·CQT에서 보이는지 눈으로 확인할 용도다.

## 3. 단계 B: 본 실행

- 데이터셋 2개를 **따로** 학습·평가한다. 섞지 않는다.
- arm 4개 × fold 5 × seed 0,1,2 × 데이터셋 2 = 120 run.
- 학습 설정은 단계 A와 같다(lr 1e-6, AdamW 0.01, batch 64, ReduceLROnPlateau, 조기 종료 patience 8, best-val-macro-F1). 클래스 수: DeepShip 4, ShipsEar 5(A–E).
- 순서: ShipsEar 전체(빠름) → DeepShip MEL → STFT → CQT → MFCC. ShipsEar 첫 run과 DeepShip 첫 run의 시간을 먼저 보고한다.

## 4. 판정 규칙 (사전 등록, 결과를 본 뒤 바꾸지 않는다)

- 주 지표 macro-F1. 보조: acc, 클래스별 F1, 혼동행렬.
- 데이터셋마다 fold별 seed 평균 → MEL 대비 paired Δ. 평균 Δ, Δ > 0인 fold 수를 보고한다.
- "MEL보다 낫다"(데이터셋별): 평균 Δ > 0 이고 4/5 fold 이상에서 Δ > 0.
- 상위 2개(E1-AE 대상, MFCC 제외): 두 데이터셋의 평균 Δ를 같은 가중치로 평균한 값의 순서로 고른다(MEL은 0). 1위와 3위의 차이가 1.1 pp 미만이면 MEL과 STFT·CQT 중 높은 쪽을 고른다.
- 두 데이터셋에서 순위가 다르면 그대로 보고한다(판정은 위 규칙을 따른다).
- MFCC 참고 해석: MEL과 1.1 pp 이내면 "미세 스펙트럼 구조가 결정적이지 않을 수 있다"(`hypothesis`)로 기록한다.
